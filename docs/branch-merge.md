# 브랜치 동기화 · 머지 관리 설계

> 상태: **1–4단계 구현됨** — 올리기 = 브랜치 + 따라가기, 받기 = 따라가기, 갈라짐 표시(1단계, `src/sync/branch.ts`·`sync.ts`), 머지 관리 목록·분류·머지 화면·최종 머지(2단계, `src/sync/merge.ts`·`src/ui/merge/MergeView.tsx`), 레이어 한정 올가미·지우개·되돌리기·확대와 작업본 저장·다시 얹기(3단계, `src/ui/merge/MergeCanvas.tsx`·`src/sync/mergeDraft.ts`). 로컬 스냅샷·자동 고정 정리·버전 기록 확장·보관함 관리(4단계, `src/sync/snapshots.ts`·`archive.ts`·`src/ui/ArchiveSheet.tsx`).

## 0. 목표와 원칙

혼자 쓰는 앱이지만 패드·컴퓨터를 자주 오간다. 지금은 올리기 때 자동 3-way 머지가 일어나고, 겹치면 "원격 우선 / 이 기기 우선"을 한 번에 고른다. 이를 **git 브랜치처럼** 바꾼다.

1. **기기마다 자기 파일(브랜치)에만 쓴다.** 한 파일을 두 기기가 덮어쓰는 일이 없으므로, 한 기기의 업로드가 다른 기기의 업로드를 지워 버리는 일(lost update)이 구조적으로 없다.
2. **머지는 사용자가 '머지 관리'에서 직접 확인하고 누른다.** 자동 머지는 없다.
3. **머지에는 삭제가 없다(모두 살리기).** 어느 한쪽에라도 있는 획은 결과에 남는다. 한 기기에서 지운 획이 다른 쪽에 남아 있으면 되살아나는 것은 감수한다 — 지우고 싶으면 머지 화면에서 지우거나, 머지 뒤 지우고 다시 올린다(§3.5).
4. **한쪽만 바뀌었으면 자동으로 따라간다(fast-forward).** 머지 관리에는 양쪽이 모두 바뀐 노트만 올라온다.
5. **네트워크는 지금처럼 사용자가 누를 때만 쓴다.** "자동 동기화 없음" 규칙(`tools/e2e/stores.ts`)은 그대로다.
6. **머지 화면은 패드(펜·손가락)와 컴퓨터(마우스·키보드)에서 똑같이 쓸 수 있어야 한다.**
7. **보관물은 눈에 보이고 정리할 수 있어야 한다.** 자동 고정(keepForever)은 하지 않는다.
8. **지우개는 획 단위만 있다.** 부분 지우개는 없앴다(`ef5658b`). 획이 잘려 새 ID 조각이 생기지 않으므로, 머지에서 획은 언제나 "있다 / 없다 / 내용이 다르다" 셋 중 하나다.

## 1. 용어

| 용어 | 뜻 |
|---|---|
| **main** | 합쳐진 결과. 받기는 main을 받는다. 노트마다 1개 |
| **브랜치** | 기기 하나가 올린 그 노트의 상태. 노트 × 기기마다 1개. 그 기기만 쓴다 |
| **세대(gen)** | main이 바뀔 때마다 1씩 오르는 번호 |
| **출발점(base)** | 이 기기가 마지막으로 맞춘 main의 세대와 그때의 내용(이 기기 로컬에 보관) |
| **고친 목록** | 브랜치가 출발점에서 *내용을 바꾼* 것(획 이동·색, 페이지 속지, 제목 등)과 바꾸기 전 해시. 브랜치 파일에 함께 실린다 |
| **fast-forward** | 한쪽만 바뀌어서 머지 없이 그대로 따라가는 것 |
| **머지하는 기기** | 지금 머지 화면을 연 기기 |
| **머지 작업본** | 머지 화면에서 옮긴 것·지운 것·바꾼 것. 최종 머지 전까지 이 기기에 저장된다 |

## 2. Drive 구조

```
Inkpad/
  docs/{docId}.json                 ← main (매니페스트 — §2.3)
  branches/{docId}@{deviceId}.json  ← 기기 브랜치 (그 기기만 쓴다, 매니페스트)
  objects/{해시}.gz                 ← 노트 조각 (청크 하나 = 페이지 하나, 내용 주소 — §2.3)
  assets/{sha256}.{ext}             ← 원본 (지금과 같음)
  backups/                          ← 옛 머지 백업 (새로 만들지 않음, 보관함 관리에서 정리)
```

- `branches/`는 한 폴더에 평평하게 두고 `appProperties`(`docId`, `kind: 'branch'`, `dev`(기기 ID), `device`, `seq`, `baseGen`, `updatedAt`, 버렸으면 `resolved`)로 찾는다. 목록 요청 1번으로 모든 브랜치 상태를 알 수 있다.
- main의 `appProperties`에는 `gen`, `mid`, `midU`(mid를 쓸 때의 updatedAt), 기기마다 `m.{deviceId}=seq`를 단다. 옛 앱은 mid를 모른 채 appProperties를 덮어쓰는데 Drive는 PATCH에 없는 키를 남긴다 — `updatedAt ≠ midU`면 옛 앱이 쓴 것으로 보고 `legacy:{updatedAt}`을 신원으로 쓴다.
- **기기 ID(`deviceId`)** 는 처음 한 번 만드는 ULID로, 바꿀 수 있는 기기 이름(`deviceName`, `src/sync/token.ts`)과 별개다. 이름을 바꿔도 브랜치는 같다.

### 2.1 main 파일에 더해지는 것

본문에는 `main` 필드로 싣는다(`DocFileV1 & { main?: MainMarker }`, `src/sync/branch.ts`).

```ts
interface MainMarker {
  gen: number
  /** main을 쓸 때마다 새로 뽑는 신원 — 출발점 비교는 세대가 아니라 이것으로 한다(동시에 따라간 두 기기가 같은 gen을 쓴다) */
  mid: string
  /** 이 main에 반영된 브랜치 — 기기별로 몇 번째 업로드(seq)까지 들어 있는가 */
  merged: Record<DeviceId, number>
  /** 이 세대를 만든 동작 — 'ff'(따라가기) | 'merge'(최종 머지) | 'restore'(되돌리기) */
  made: { kind: 'ff' | 'merge' | 'restore'; deviceId: DeviceId; device: string; at: number }
}
```

### 2.2 브랜치 파일

본문에는 `branch` 필드로 싣는다(`DocFileV1 & { branch: BranchMarker }`).

```ts
interface BranchMarker {
  deviceId: DeviceId
  device: string
  seq: number          // 이 기기가 이 노트 브랜치를 올린 횟수 (1, 2, 3 …) — 앞으로만 간다
  baseGen: number      // 출발점 main 세대
  baseMid: string | null // 출발점 main 신원 (모르면 null)
  /** 출발점 대비 내용을 바꾼 것 — 키: 'el:{id}' | 'page:{id}' | 'block:{id}' | 'doc:title' | 'doc:category' | 'doc:mode' | 'doc:pageOrder' */
  modified: Record<string, /* 바꾸기 전 내용의 해시 */ string>
}
```

- 머지는 대부분 **있다/없다**만 보면 되므로 추가·삭제 목록은 싣지 않는다(모두 살리기라 구분할 필요가 없다).
- **고친 목록**만 필요하다. 같은 ID가 양쪽에 있는데 내용이 다를 때 "누가 고쳤나"를 알아야 하기 때문이다. 바꾸기 전 해시가 있으면 머지하는 기기는 그 브랜치의 출발점 내용 없이도 판정할 수 있다 — 옛 main 리비전을 내려받을 필요가 없으므로 고정(keepForever)도 필요 없다.
- 해시는 지금 `merge.ts`가 쓰는 비교용 직렬화(`sig`)의 짧은 해시다.

### 2.3 조각과 매니페스트 (바뀐 페이지만 오가기, `src/sync/objects.ts`)

획 하나를 고쳐도 노트 전체를 두 번(브랜치 + main) 올리던 것을 git의 객체처럼 바꿨다.

- **조각**: 청크(페이지 노트는 페이지 하나 = 청크 하나) 요소 배열을 gzip한 파일. 이름은 요소 JSON의 sha256(앞 40자) — 내용이 같으면 같은 조각이다.
- **매니페스트**: main·브랜치 본문. 청크 대신 `objs: {pageId, key, h, f(파일 id), n, s}[]`를 싣는다. `kind: 'inkpad-doc-m'` — 옛 앱은 노트로 읽지 않고 건너뛴다(청크 없는 노트로 덮지 않는다). appProperties `nb`는 노트 전체 조각 크기(받기 미리보기의 최대 용량).
- **올리기**: 이 기기가 아는 조각(마지막으로 읽거나 쓴 main과 내 브랜치가 가리킨 것, 14일 안에 확인한 것만)은 다시 올리지 않는다. 브랜치를 올린 뒤 main을 따라갈 때는 같은 조각을 가리키므로 바뀐 페이지만 한 번 올라간다. 휴지통에 있는 조각은 다시 가리키지 않고 새로 올린다(올리기마다 휴지통 목록 한 번).
- **받기**: 이 기기의 기준본·현재 노트에 같은 해시가 있으면 받지 않는다. 받은 조각은 해시를 확인하고, 못 읽으면 그 노트를 건너뛰고 알린다(이 기기 노트는 그대로).
- **옛 전체 파일**(`kind: 'inkpad-doc'`)도 그대로 읽는다 — 옛 리비전·머지 백업·옛 앱이 올린 main. 이 기기가 다시 올리면 매니페스트가 된다. 이 기기 안(기준본·스냅샷)은 전체 파일 그대로다.
- **버전 기록**: main 리비전은 매니페스트다. 되돌리기·미리보기는 조각을 모아 풀고, 고정 해제는 매니페스트를 그대로 다시 올린다.
- 측정(`npm run test:e2e -- delta`, 10쪽·획 800개): 노트 254KB — 첫 올리기 256KB(예전 약 510KB), 획 하나 올리기 27KB(예전 약 510KB), 획 하나 받기 26KB(예전 254KB).

**받기 목록**: 받기·받기 미리보기는 마지막으로 본 목록에 그 뒤 바뀐 파일(`modifiedTime >` 본 것 중 가장 늦은 시각 − 1시간)만 더한다. main은 본문을 올릴 때만 바뀌므로 충분하다. 휴지통으로 간 파일은 보이지 않으므로 하루에 한 번, 그리고 동기화 패널 목록·머지 관리 목록이 전체를 다시 읽는다. 이 기기가 main을 쓰거나 지우면 기억한 목록을 바로 고친다.

## 3. 동작

### 3.1 상태 판정 (노트 하나, 이 기기 기준)

| 이 기기에 올리지 않은 변경 | main이 내 출발점 이후 바뀜 | 상태 | 하는 일 |
|---|---|---|---|
| 없음 | 아니오 | 최신 | — |
| 없음 | 예 | 받을 것 (파란 점) | 받기 = main으로 따라가기 |
| 있음 | 아니오 | 올릴 것 | 올리기 = 브랜치 업로드 → main 따라가기(ff) |
| 있음 | 예 | **갈라짐** (새 표시) | 올리기 = 브랜치 업로드만 → **머지 관리**에 올라옴 |

- 내 브랜치가 아직 main에 반영되지 않았으면(`내 seq > main.merged[나]`) 올리지 않은 변경이 없어도 **갈라짐**으로 본다. main을 받아 덮으면 이 기기 화면에서 내 변경이 사라져 보이기 때문이다(브랜치에는 남아 있다).
- 다른 기기의 브랜치가 갈라진 상태면, 이 기기에서도 그 노트가 머지 관리에 보인다. 어느 기기에서든 머지할 수 있다.

### 3.2 올리기

1. 이 기기 브랜치를 올린다(`seq + 1`, 고친 목록 포함). 이 파일은 이 기기만 쓰므로 경합이 없다.
2. main이 내 출발점 세대 그대로면 main을 이 내용으로 바꾼다(ff, `gen + 1`, `merged[나] = seq`). 출발점도 새 main으로 옮긴다.
3. main이 그 사이 바뀌었으면 main은 건드리지 않는다. 노트는 "갈라짐"이 되어 머지 관리에 올라온다.

**main 쓰기 경합은 데이터를 잃지 않는다.** 두 기기가 동시에 2를 해서 한쪽 main 쓰기가 덮이더라도, 진 쪽 내용은 그 기기 브랜치에 그대로 있다. `seq > main.merged[그 기기]`이므로 다음 목록 새로고침에서 머지 관리에 다시 나타난다. main은 브랜치들에서 다시 만들 수 있는 결과물이고, 원본은 브랜치들이다. main을 쓰기 직전에 세대를 한 번 더 확인해 경합 창도 좁힌다.

### 3.3 받기

받기는 **클라우드로 완전 동기화**다 — 노트에 써 보며 공부하고 클라우드 상태로 되돌리는 쓰임에 맞춘다.

- 이 기기 변경이 없는 노트: main을 받아 적용하고 출발점을 옮긴다(따라가기).
- 이 기기 변경이 있는 노트(올릴 것·갈라짐): 미리보기의 **'이 기기 내용이 덮이는 노트'**에 변경 수(+새로 쓴 획 −지운 획)와 함께 뜨고, 노트마다 **덮기(기본)·올리기·건너뛰기**를 고른다. **비교**는 기준본(마지막으로 맞춘 상태) 위에 이 기기 변경을 그린다(`sync/localChanges.ts` — 머지 엔진 classify를 재사용, 네트워크 없음, `ui/ChangesView.tsx`).
  - **덮기**: 이 기기 내용은 **로컬 스냅샷으로만** 남기고 브랜치에 올리지 않는다(공부용 낙서가 브랜치·머지 대기로 쌓이지 않게). 내 브랜치의 머지 안 된 내용은 버린 것(resolved)으로 표시한다. main이 이 기기 출발점 그대로면 기준본으로 되돌리기만 한다 — 내려받기·쓰기 0.
  - **올리기**: 그 노트를 먼저 올린다(따라가기, 또는 갈라졌으면 브랜치로 → 머지 관리).
  - **건너뛰기**: 그대로 둔다.
- **변경 버리기**: 받기와 따로, 기준본으로 되돌린다 — 오프라인에서도, 네트워크 0. 지금 내용은 스냅샷('변경 버리기 전')으로 남는다.
- 자동 재정렬(내 브랜치가 반영된 뒤의 새 변경만 새 main 위에 다시 얹기)은 하지 않는다 — 받기를 자주 하는 쓰임이라 필요가 적다.

### 3.4 머지 관리 (목록)

설정 > 동기화 옆에 **머지 관리** 화면을 둔다. 라이브러리 상단에는 개수 배지를 단다.

- 행 하나 = 갈라진 노트 하나: 제목, 양쪽 기기(예: `컴퓨터(main) · 15:20 ↔ iPad · 16:02`), 변화 요약(`iPad에만 +34 · 컴퓨터에만 12 · 양쪽 고침 1`).
- 한 노트에 갈라진 브랜치가 둘 이상이면(기기 3대) **하나씩 차례로** 합친다. 머지 화면은 늘 "main ↔ 브랜치 하나"의 두 쪽만 보여 준다 — 화면과 규칙이 단순해진다. 먼저 합친 결과가 다음 머지의 main이 된다.
- 행을 누르면 **머지 화면**을 연다. 작업본이 있는 노트는 "작업 중" 표시를 단다.

### 3.5 지운 획이 되살아났을 때

모두 살리기라서 머지 뒤 지운 획이 되살아날 수 있다. 지우고 다시 올리면 된다 — **다른 기기가 그 노트를 손대지 않았다면** 한쪽만 바뀐 것이므로 ff로 main에 그대로 반영되고 삭제가 유지된다. 다른 기기도 그 사이 고쳤다면 다시 갈라짐이 되어, 다음 머지에서 또 되살아난다. 그래서 기기를 바꿀 때 **"받고 → 쓰고 → 올리기"** 습관을 권한다.

| 상황 | 결과 |
|---|---|
| 머지 뒤 컴퓨터에서 되살아난 획을 지우고 올림, 패드는 그사이 손대지 않음 | ff → 삭제 유지. 패드는 받기로 따라옴 |
| 컴퓨터에서 지우고 올림, 패드도 그사이 같은 노트에 씀 | 갈라짐 → 머지 → 모두 살리기라 다시 살아남 |

## 4. 머지 규칙 (main ↔ 브랜치 하나)

두 쪽 이름은 기기 이름으로 보여 준다. main 쪽은 main을 마지막으로 만든 기기(`made.device`)다.

| 분류(레이어) | 판정 | 결과 |
|---|---|---|
| **공통** | 양쪽에 같은 내용으로 있음 | 그대로 |
| **[main 쪽 기기]에만** | main에만 있음 (그쪽이 새로 그렸거나, 브랜치가 지운 것) | **남김** |
| **[브랜치 기기]에만** | 브랜치에만 있음 (그쪽이 새로 그렸거나, main 쪽이 지운 것) | **남김** |
| **한쪽만 고침** | 양쪽에 있는데 내용이 다르고, 한쪽만 출발점에서 바꿈 | **고친 쪽** |
| **양쪽 고침** | 양쪽이 다 출발점에서 바꿈 | **머지하는 기기의 것** (머지하는 기기가 두 쪽 어디에도 아니면 main 쪽) |

"한쪽만 고침 / 양쪽 고침"은 브랜치의 고친 목록으로 판정한다.

- 브랜치 고친 목록에 없음 → 브랜치는 출발점 그대로 → main 쪽이 고친 것
- 있고, main의 해시 = 바꾸기 전 해시 → 브랜치만 고친 것
- 있고, main의 해시 ≠ 바꾸기 전 해시 → 양쪽 고침

어느 결과든 머지 화면에서 올가미로 "다른 쪽 버전으로 바꾸기"를 할 수 있다.

**획이 아닌 것도 같은 원칙이다.**

- **페이지**: 한쪽에만 있는 페이지는 남긴다. 순서는 main 순서를 따르고, 브랜치에만 있는 페이지는 브랜치 순서에서 바로 앞 페이지 뒤에 끼운다. 속지·크기는 위 표의 고침 규칙을 따른다.
- **제목·카테고리·모드**: 고침 규칙(한쪽만 → 고친 쪽, 양쪽 → 머지하는 기기 것). 머지 화면 상단에서 바꿀 수 있다.
- **블록(메모 등)**: 획과 같다. 블록은 지울 때 삭제 표식(`deletedAt`)을 남기는데, 모두 살리기이므로 한쪽이 지우고 다른 쪽에 살아 있으면 살아 있는 쪽을 남긴다. 지금 코드의 `updatedAt` 비교는 쓰지 않는다.
- **원본(PDF·이미지)**: 합집합이다.

## 5. 머지 화면 (패드·컴퓨터 공용)

지금 편집기 엔진을 **머지 모드**로 연다. 처음 그려지는 것은 §4 규칙으로 만든 결과이고, 머지 화면에서 한 편집은 작업본에만 쌓인다.

### 5.1 화면 구성

```
┌───────────────────────────────────────────────┬──────────────────────┐
│ ← 머지: 물리 노트          [결과만 보기]    ⟲ ⟳ │ 레이어                │
│                                                 │ ● 공통          1,204 │
│                                                 │ ◉ 컴퓨터에만     +12  │
│               (캔버스)                           │ ◉ iPad에만       +34  │
│                                                 │ ◉ 고친 획          3  │
│                                                 │                      │
│ [올가미] [지우개]                  ◀ 변경 3/9 ▶ │ [나중에]  [최종 머지] │
└───────────────────────────────────────────────┴──────────────────────┘
```

- 폭이 900px 이상이면 레이어를 오른쪽 패널로, 좁으면(패드 세로·작은 창) 아래쪽 시트로 둔다. 같은 컴포넌트다.
- 모든 버튼은 손가락으로 누를 수 있게 44px 이상으로 한다.

### 5.2 레이어 보기

- 획 색은 바꾸지 않는다. 노트 자체가 여러 색이라 색을 입히면 헷갈린다. 대신:
  - **선택한 레이어**는 원래대로, 나머지는 흐리게(약 25%) 그린다.
  - 기기마다 정해진 표시 색으로 **획 둘레에 숨쉬는 빛 테두리**를 그린다(획과 빛 사이에 흰 틈 — 같은 색 펜과 갈린다, 켜고 끌 수 있음, 결과만 보기에서는 끔).
- 레이어 행: 눈 아이콘(보이기/숨기기), 탭 = "이 레이어 선택(편집 대상)", 개수, "이 레이어 전부 버리기".
- **고친 획** 레이어는 한쪽만 고침·양쪽 고침을 함께 담고, 획마다 어느 쪽 버전이 쓰였는지 표시한다.
- **◀ 변경 n/N ▶**: 다음 변경(한쪽에만 있는 획·고친 획)이 있는 곳으로 화면을 옮긴다(페이지 넘김 + 확대).

### 5.3 도구 (선택한 레이어에만 적용)

| 도구 | 동작 |
|---|---|
| 올가미 | 선택한 레이어의 획만 고른다 → 끌어 옮기기, 버리기, 색 바꾸기, 다른 쪽 버전으로 바꾸기(고친 획) |
| 지우개 | 선택한 레이어의 획만 획 단위로 지운다. 예: "컴퓨터에만 있는 획 중 이 부분만 지우기" |
| 되돌리기 / 다시 | 머지 화면 안의 작업만 되돌린다 |

- 1차 구현에서 머지 화면에서는 새로 그리지 않는다. 펜은 없다(§9 열린 질문 2).
- **입력** — 지금 편집기와 같은 규칙을 쓴다:
  - 패드: 펜 = 도구, 손가락 = 이동·확대, 두 손가락 탭 = 되돌리기
  - 컴퓨터: 마우스 = 도구, 휠·트랙패드 = 이동·확대, 스페이스 + 끌기 = 이동
  - 단축키: `1`–`4` 레이어 선택, `H` 숨기기, `L` 올가미, `E` 지우개, `Backspace` 버리기, `⌘Z`/`⇧⌘Z`, `]`/`[` 다음/이전 변경

### 5.4 작업본과 최종 머지

- 모든 편집은 **머지 작업본**(IndexedDB `mergeDrafts`)에 바로 저장된다. 앱이 꺼져도 이어서 할 수 있다. "나중에"는 작업본을 둔 채 닫는다.
- 작업본은 입력들의 버전(main 세대, 브랜치 seq)을 기억한다. 다시 열었는데 입력이 바뀌었으면(다른 기기가 또 올림) 알리고, 한 편집을 획 ID 기준으로 새 입력에 다시 적용한다.
- **최종 머지**를 누르면:
  1. 결과 내용을 만든다.
  2. 이 기기에 덮이기 전 상태를 **로컬 스냅샷**으로 남긴다(§6).
  3. main을 쓴다: `gen + 1`, `merged[브랜치 기기] = seq`, `made.kind = 'merge'`. 쓰기 직전 세대를 다시 확인하고, 그 사이 바뀌었으면 작업본을 새 main 위에 다시 적용해 한 번 더 보여 준다.
  4. 이 기기에 적용하고 출발점을 옮긴다. 다른 기기는 다음 받기 때 따라온다(그 기기 브랜치가 이미 반영됐으므로 ff).
- 머지하는 기기 자신에게 올리지 않은 변경이 있으면, 머지 화면을 열기 전에 "먼저 올리기"를 하게 한다 — 이 기기의 최신 상태가 브랜치로 올라가야 머지에 들어간다.

## 6. 버전 기록과 보관함 관리

| 무엇 | 어디 | 정리 |
|---|---|---|
| main 세대 | `docs/{docId}.json`의 Drive 리비전 | Drive가 30일 뒤 자동 정리. 사용자가 직접 고정한 것만 남는다 |
| 기기 브랜치 | `branches/…` 파일 (그 리비전 = 그 기기의 업로드 기록) | 보관함 관리에서 브랜치 삭제 |
| 로컬 스냅샷 | 이 기기 IndexedDB | 노트당 최근 20개 + 전체 용량 상한(기본 200MB). 넘으면 오래된 것부터 지운다 |
| 옛 머지 백업 | `backups/` | 새로 만들지 않는다. 보관함 관리에서 일괄 정리 |

- **머지 백업이 더는 필요 없다.** 머지에 들어간 두 쪽은 main 리비전과 브랜치 파일에 그대로 남는다.
- **로컬 스냅샷**은 이 기기 내용이 덮이기 직전(받기·맞추기의 덮기, 변경 버리기, 최종 머지, 되돌리기)에 자동으로 남는다. 네트워크 없이 되돌릴 수 있는 안전망이다.
- **자동 고정은 없다.** 되돌리기 때 리비전을 고정하던 동작(`revisions.ts`의 `restoreDocRevision`, `sync.ts`의 되돌림 업로드)을 없앤다. 고정은 사용자가 버전 기록에서 직접 누른 것만 한다.
  - ⚠️ 확인할 것: 코드는 "고정한 리비전만 내려받을 수 있다"고 가정한다. 실제 Drive에서 고정 없이 내려받을 수 있는지 한 번 실험한다. 안 된다면, 고정하지 않은 리비전 되돌리기는 "고정 1칸을 쓴다"고 알리고, 그 고정에 '되돌리기용' 표식을 달아 정리 대상으로 보여 준다.
- **보관함 관리 화면** (설정 > 동기화 > 보관함):
  - 노트별: 브랜치(기기·마지막 업로드·머지됨/안 됨), 고정 수(n/200), 로컬 스냅샷 수·용량, 옛 백업 수·용량
  - 일괄 정리:
    - 머지 끝난 브랜치 지우기 (머지 안 된 브랜치는 경고 후에만)
    - 쓰지 않는 기기의 브랜치 지우기: 기기 목록에서 기기를 '퇴역' 처리하면 그 기기 브랜치를 한 번에 정리
    - 오래된 로컬 스냅샷 지우기
    - 옛 머지 백업 모두 지우기
    - 클라우드에서 지운 노트의 남은 파일 지우기
- **버전 기록 패널**은 한 목록에 main 세대(따라가기·머지·되돌리기 표시), 기기별 브랜치 업로드, 로컬 스냅샷을 시간순으로 보여 준다. 되돌리기 전에 미리보기(썸네일 + `획 +12 / −3` 요약)를 보여 준다.
- **되돌리기**는 그 내용을 이 기기에 적용하고 "올리지 않은 변경"으로 만든다. 그다음은 보통의 올리기 흐름(브랜치 → ff 또는 머지 관리)을 탄다.

### 6.1 안 쓰는 조각 정리

노트를 고치면 옛 조각이 남는다. 보관함 관리의 **노트 조각 → 조각 살펴보기**가 모든 main·브랜치와 고정한 리비전의 매니페스트를 읽어(조각 목록만, 노트마다 리비전 목록 한 번) 가리키는 조각을 모은다. **안 쓰는 조각 정리**는 두 번에 걸쳐 지운다.

1. 아무도 가리키지 않는 조각에 '안 씀' 표식(`unref=시각`)을 단다. 다시 가리키게 된 조각은 표식을 지운다.
2. 표식을 단 지 45일이 지나도 여전히 아무도 가리키지 않으면 Drive 휴지통으로(30일 뒤 Drive가 지운다).

45일은 고정하지 않은 옛 리비전(약 30일 산다)이 그 조각을 가리킬 수 있는 기간보다 길다. 올리기는 14일 안에 확인한 조각만 다시 가리키고 휴지통의 조각은 새로 올리므로, 정리와 올리기가 겹쳐도 노트가 깨지지 않는다.

각 단계는 따로 PR로 내고, 단계마다 지금 쓰는 기능이 깨지지 않게 한다.

## 8.1 수동 동기화 편의 (4단계 뒤)

네트워크를 저절로 쓰지 않는 원칙을 지키면서 놓치지 않게 '보여 주기'로 해결한다 (`src/app/syncReminders.ts`, `src/ui/editor/NoteSyncChip.tsx`).

|---|---|---|
| 편집 화면 노트 칩(상태 + 이 노트만 올리기·받기·머지) | 누를 때만 | 켬 |
| 노트를 닫을 때 '올리지 않은 변경' 알림 → '정리'(비교 화면: 올리기·변경 버리기) | 없음(누를 때만) | 켬 |

## 9. 결정 사항과 열린 질문

**확정**

- 머지에는 삭제가 없다(모두 살리기). 지운 획이 되살아나는 것은 감수하고, 지우고 다시 올려 정리한다.
- 고친 획: 한쪽만 고쳤으면 고친 쪽, 양쪽이 고쳤으면 머지하는 기기 쪽.
- 지우개는 획 단위만 (부분 지우개 제거).
- 한쪽만 바뀌었으면 자동으로 따라간다(fast-forward).
- 머지 화면은 패드·컴퓨터 공용이다.
- 저장소는 Google Drive를 유지하고, 동기화는 수동을 유지한다.

**설계에서 정한 것** (이의가 있으면 바꾼다)

- 머지 화면은 편집 엔진 대신 가벼운 캔버스(아래: 속지·획, 위: 올가미·선택·끌기 덮개)로 그리고 입력도 직접 받는다. 엔진은 DB에 바로 쓰는 구조라, 작업본에만 쌓아야 하는 머지에 맞추려면 고칠 곳이 많았다. 그래서 확대는 단계 버튼(100–300%)이고 두 손가락 확대는 없다.
- 작업본은 `mergeDrafts` 테이블 대신 기기 로컬 KV(`syncState`의 `mergeDraft:{docId}@{기기 ID}`)에 둔다 — 스키마를 바꾸지 않는다.
- 작업본의 옮김·색은 항목 키에 붙은 값이라, 다른 쪽 버전으로 바꿔도 그대로 얹힌다. 무한 캔버스에서 옮긴 획은 시작점이 들어간 청크로 다시 배치한다(엔진과 같은 규칙).
- 올가미·지우개는 '보기' 도구에서는 동작하지 않는다 — 도구를 고르지 않으면 펜·손가락 모두 화면 스크롤이다.
- 로컬 스냅샷은 새 테이블 대신 기존 `backups` 테이블(reason `snapshot:{docId}`)에 둔다 — 스키마를 바꾸지 않는다.
- 되돌리기는 먼저 고정 없이 리비전을 받아 보고, Drive가 거부할 때만 고정한다(§6의 '확인할 것'을 실제 Drive 동작에 맡기는 방식). 미리보기는 고정하지 않는다 — 고정이 필요하면 그렇다고 알린다.
- 버전 기록의 브랜치는 기기마다 최신 업로드 하나만 보여 준다(브랜치 파일의 옛 리비전은 목록 요청이 기기 수만큼 늘어 넣지 않았다).
- '노트가 사라진 뒤 남은 파일'은 main이 없고 하루 넘게 지난 브랜치·백업만 — 막 만든 노트의 main이 아직 안 올라간 순간을 지우지 않게.
- 고정 수(n/200)는 노트마다 리비전 목록을 따로 읽어야 해서 보관함 화면에는 넣지 않았다 — 노트별 버전 기록 패널에 고정 용량으로 보인다.
- 공통 항목은 버릴 수 없다 — 양쪽이 같은 것을 갖고 있어 버리면 '삭제'가 된다(머지에는 삭제가 없다). 지우려면 머지 뒤 지우고 올린다.

- 갈라진 브랜치가 여럿이면 하나씩 차례로 합친다(머지 화면은 늘 두 쪽).
- 머지하는 기기가 두 쪽 어디에도 아니면(기기 3대), 양쪽 고침은 main 쪽을 따른다.
- 머지 화면을 열기 전에 머지하는 기기의 올리지 않은 변경을 먼저 올린다.
